# US-001: Initialize Full-Stack Workspace Baseline

## Epic Link
- Epic ID: EP-TECH-001
- Epic Name: Platform and Delivery Bootstrap

## User Story
As a developer,
I want a runnable Next.js workspace with API route scaffolding and environment profiles,
so that the team can implement features quickly without setup friction.

## Business Value
- Enables parallel team delivery from day one.
- Reduces integration churn across frontend and backend route handlers.

## Acceptance Criteria
1. Project runs locally with a documented start command.
2. App Router pages and API route structure are created for chat and patient profile endpoints.
3. Environment profiles support local development and production defaults.
4. Basic health-check endpoint returns success.
5. Error handling baseline exists for API route failures.

## Implementation Evidence Checklist (2026-07-29)
1. AC-001: **Pass**
	- Evidence: `npm run dev` startup validated (clean run on port 3020) and local app shell reachable (`GET /` = `200`).
2. AC-002: **Pass**
	- Evidence: App Router pages exist for `/`, `/chat`, `/profile`; API routes exist for `/api/health`, `/api/chat`, `/api/patient-profile`.
3. AC-003: **Pass**
	- Evidence: `.env.example` includes local/production profile keys and request-time integration keys.
4. AC-004: **Pass**
	- Evidence: `GET /api/health` returns `200` with structured JSON status payload.
5. AC-005: **Pass**
	- Evidence: Shared route error handler returns consistent JSON shape; missing required env keys return `CONFIG_MISSING` responses instead of raw stack traces.
